# 架构图生成提示词

请帮我生成一张项目架构图，要求不要简单罗列技术栈，而是按架构语义分组。

请先分析项目结构、模块边界、主要业务能力和外部依赖，然后按以下视角组织：

1. 前端/入口层：用户入口、主要页面或客户端能力。
2. 后端模块层：优先按代码模块、服务模块或包边界分组，不要把 Controller、Service 和模块平级罗列。
3. 核心能力域：在模块内部标出主要业务能力，例如认证、订单、内容管理、任务调度、报表、搜索、支付、消息通知、智能能力等。
4. 外部依赖：按角色分类，而不是全放一层：
   - Runtime Dependencies：数据库、缓存、消息队列、对象存储、配置中心等。
   - External Capability Providers：支付、短信、地图、邮件、对象存储、模型服务等外部能力。
   - Platform / Ops：部署、监控、日志、链路追踪、CI/CD 等。
   - External Actors / Systems：外部业务系统、第三方应用、被管理对象、Webhook 调用方等。
5. 用连线表达“谁依赖谁”，但 README/技术方案总览图默认只画“模块 → 外部依赖分组/关键外部组件”的连线，不要从模块内部的每个能力块分别拉线。能力块到具体依赖的细粒度连线只适合详细设计图或专题图。
6. 图上只放关键组件，避免把依赖清单、类名清单、技术细节全部塞进去。
7. 模块内部可以展示核心能力域，但这些能力域主要用于解释模块职责；除非某个依赖关系对理解架构非常关键，否则不要让能力域承担主要连线。

请输出一版适合 README/技术方案文档使用的架构图，并说明每个分组的依据。
