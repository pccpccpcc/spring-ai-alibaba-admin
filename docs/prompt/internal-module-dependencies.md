# 内部模块依赖图生成提示词

请帮我生成一张项目内部模块依赖图，目标是表达代码模块之间的直接依赖关系，而不是展示完整业务架构或外部中间件。

请先分析项目的构建文件和模块声明，例如 Maven `pom.xml`、Gradle 配置、包结构或 workspace 配置，然后按以下规则组织图：

1. 只展示项目内部模块，不展示第三方依赖、数据库、缓存、消息队列、外部服务或部署组件。
2. 以构建系统中的真实直接依赖为准：
   - 如果 A 的构建文件直接依赖 B，则画 `A -> B`。
   - 不要把传递依赖画成直接依赖，除非构建文件里显式声明。
3. 按依赖层级排布模块：
   - Entry / App 层：启动模块、聚合模块、可运行应用。
   - Interface / Adapter 层：对外 API、开放接口、适配器模块。
   - Core / Domain 层：核心业务逻辑、领域服务、引擎。
   - Base / Runtime 层：领域模型、DTO、公共运行时对象、基础工具。
4. 模块卡片中只放简短职责摘要和直接依赖数量，不要塞入 Controller、Service、类名或技术栈清单。
5. 用单向箭头表达依赖方向，箭头从“依赖方”指向“被依赖方”。
6. 如果存在跨层直接依赖，可以保留，但要标注为“direct dependency”，不要暗示它一定是不合理的。
7. 如果图是 DAG，请标明无循环依赖；如果存在循环依赖，要高亮循环并说明风险。
8. 图面应适合 README/技术方案文档阅读：模块少时优先清晰、留白和依赖方向，不要过度装饰。

请输出一版 SVG 或 Mermaid 架构图，并说明每个模块分层和每条依赖边的依据。
